## 시뮬(에뮬레이터)에서 확인한 것 (10/14)

- Y0 에서 25 cm 24방향 중 20방향을 560 mm/s 로 완주, **두산 알람 없음**(좌우 0°·15°·165°·180° 는 관절 80 % 경계라 스크립트가 뺌 → 540 으로 다시). 계획 단계 관절 속도 % 가 모델과 같음.
- 가속별 이동 시간(명령 지연 뺀 중앙값, 20방향): **2000 0.637 · 3000 0.545 (−14 %) · 4000 0.541 (8방향)**. 3000 → 4000 은 효과 없음. 가속 4000 까지 에뮬레이터 거부 없음.
- 에뮬레이터는 충돌 모델·힘이 없다 → 아래 실로봇 확인이 필요한 이유.

## ⚠ 시간 예산과 맞춰 보기 (먼저 읽기)

`MODE3_PLAN.md` 8절: 명령(공 놓은 뒤 0.16 s) → 공 도착 0.745 s = **예산 ≈ 0.58 s** (명령 기준, 출발 지연 0.1 s 포함).

| 가속 | 15 cm | 20 cm | 25 cm |
|---|---|---|---|
| 2000 | 0.55 + 0.1 = **0.65** | 0.63 + 0.1 = 0.73 | 0.71 + 0.1 = 0.81 |
| 3000 | 0.45 + 0.1 = **0.55** ✅ | 0.52 + 0.1 = 0.62 | 0.58 + 0.1 = 0.68 |

→ **지금 투구 속도에서는 25 cm 는 어느 자세·가속으로도 제시간에 못 간다.** Y0 + 가속 3000 의 현실적 의미는 "**15 cm 전 방향(360°)을 예산 안(0.55 s)에**" 이고, 20 cm 는 경계. 25 cm 반경은 투구가 더 느리거나 멀 때(비행 1 s 이상)만 쓸 수 있다. 이 전제를 정정인·박성현이 받아들이면 아래로 진행.

## 안전 (꼭)

- 로봇이 움직인다 ⚠. 비상정지 손 닿는 곳, 반경 1 m 안 사람 없음, 패드 쥔 상태(38 N).
- **Y0 는 팔 모양이 지금과 다르다**(팔꿈치 접힘, J3 +100°). 관측 자세 → Y0 movej 경로가 테이블·거치대에 닿는지 **처음은 펜던트 수동/저속**으로.
- 시험 동안만 `ros2 param set` 으로 바꾸고 끝나면 원복 확인. `safety.yaml` 파일은 고치지 않는다.
  - 작업 공간 x: `workspace_x_max_m` 0.57 → **0.78** (Y0 요격 경로 TCP x 최대 0.734. 투구자는 J1 에서 3 m 밖) — **정정인 동의 뒤**
  - 힘 한계: 이동만 하는 시험은 받기 창이 안 열리므로 `force_limit_n` 25 → **80** (10/12 와 같은 시험값). 가속 3000 은 90~110 N 예상이라 **80 N STOP 이 나면 그 값을 기록하고 끝**(110 N 까지 올려 다시 할지는 정정인 결정)
- 가속 4000 은 하지 않는다(시뮬에서 3000 과 차이 없음, 힘 120~145 N 예상으로 130 N 창 초과).

## 순서 (터미널 3)

**0. 계획만 (로봇 안 움직임)** — 관절 속도 %·작업 공간 판정이 시뮬과 같은지
```bash
python3 scripts/mode3_reach_test.py --posj -58.7 7.0 100.2 98.8 63.6 -100.3 --angles $(seq 0 15 345) --dist 15 25 --vel 540 --ws-x-max 0.78
```

**1. Y0 로 이동 + 저속 도달 (팔뚝-기둥 확인)** — `--posj` 가 먼저 movej(20 °/s) 한다. 첫 실행은 **왼쪽(180°)·위-왼쪽(135·150·165°) 25 cm 를 100 mm/s** 로. 팔뚝이 베이스 기둥에 7 cm 까지 가는 경로. 두산 자기충돌 정지·펜던트 알람 여부, `print_pose.py` 로 TCP (0.56, −0.32, 0.43) 확인.
```bash
python3 scripts/mode3_reach_test.py --run --posj -58.7 7.0 100.2 98.8 63.6 -100.3 --angles 135 150 165 180 --dist 25 --vel 100 --acc 500 --reps 1 --ws-x-max 0.78
```

**2. 가속 2000 · 15 cm 전 방향** — 기준선. 방향별 도착 시간·힘 최대 (#144 표와 같은 형식)
```bash
python3 scripts/mode3_reach_test.py --run --posj -58.7 7.0 100.2 98.8 63.6 -100.3 --angles $(seq 0 30 330) --dist 15 --vel 540 --acc 2000 --reps 2 --ws-x-max 0.78
```

**3. 가속 3000 · 15 cm 전 방향** — 핵심. 도착 시간이 2000 대비 −13 % 근처인지, **힘 최대가 110 N 안인지**(옆 0°·180° 가 가장 큼). 80 N STOP 이 나면 그 방향·값 기록 후 중단.
```bash
python3 scripts/mode3_reach_test.py --run --posj -58.7 7.0 100.2 98.8 63.6 -100.3 --angles $(seq 0 30 330) --dist 15 --vel 540 --acc 3000 --reps 2 --ws-x-max 0.78
```

**4. (3 이 되면) 가속 3000 · 25 cm** — 힘 상한 확인용. 시간은 예산 밖이라 참고값.
```bash
python3 scripts/mode3_reach_test.py --run --posj -58.7 7.0 100.2 98.8 63.6 -100.3 --angles $(seq 0 30 330) --dist 25 --vel 540 --acc 3000 --reps 1 --ws-x-max 0.78
```

**5. 카메라** — Y0 에서 손목 카메라(광축 정면 3°)에 투구 위치가 보이는지, 측면 RealSense 에 패드가 보이는지 `rqt_image_view`.

**6. 받기 시험** (1~5 통과 뒤, 값 적용 후) — `mode3_catch_loop.py --count 10`. 받기 창 130 N 안에서 STOP 없는지, 결과·힘 최대 기록 (#173 과 같은 형식).

끝: bag Ctrl+C → `ros2 param set /rally_safety_monitor workspace_x_max_m 0.57` · `force_limit_n 25.0` → `ros2 param get` 으로 원복 확인.
